# 自动故障处理调度器与离线验收

本轮在 `1a8fa15` 的事务提交、断点和共享 worker 准入基础上，实现生成产物的自动修复闭环。项目管理 ID：`YH-20260710-002`；开发者：范震。分析内容、章节 Markdown 的十节要求、Delta/治理 JSON 契约和终稿 strict 校验均保留。

## 调度流程

普通生成或提交发现产物错误后，统一进入 `fault_recovery.recover_artifact`。适用入口为章节分析、章节 Delta、周期治理和最终草稿，包括工作台治理/终稿入口。已有确定性纠错仍先执行；能直接通过原校验器的问题不需要请求模型。

1. 为失败产物、原文、章节分析和相关正式结构建立副本，保存原始失败文件。
2. 第一策略定点修复；失败后第二策略重新核对原文证据、正式名称与历史反馈；仍失败则第三策略先独立诊断，再按诊断修复。
3. 每个候选先检查内容保全，再运行原有校验与合并流程。校验运行于重新构造的干净副本，不能使用模型写出的“成功报告”或提交凭据。
4. 程序检查通过后，再单独请求模型复核内容保全、原契约和证据支持。复核结果必须与候选摘要绑定，全部检查通过、问题列表为空且复核期间候选未改动，才允许发布。
5. 发布前核对正式输入是否变化；通过后原子写入产物，由现有幂等提交逻辑发布正式结构并继续流水线。修复提交的章节仍执行原定周期治理，不跳过检查。

第三策略可用环境变量 `ND_RECOVERY_COMMAND` 配置另一个兼容现有 worker 协议的模型命令；未配置时使用当前模型进行独立诊断，不自动购买或选择未授权服务。单纯换策略默认可用，不需要用户逐次确认。

## 内容和故障边界

- JSON 原字段和列表项不可通过删除来规避错误；按原契约迁入同一元素“详情”的字段比较原值，允许无损位置调整。长叙述保留原文，必要时补充；根级“质量说明”更新由程序在原字符串字段中保留旧说明并追加新说明。名称等标识符可纠正。Markdown 保留原有非标题内容行，允许修复标题与补充内容。损坏 JSON 尽可能保留可解析的叙述字符串，再交独立复核。
- 内容保全检查属于保守的机械检查，不等同于语义正确性证明。错误结论须保留追溯并补充有原文依据的纠正说明；模型仍可能判断错误，因此原程序验收和独立复核均不能省略。
- 原生结构化输出继续使用原 Delta/治理 schema。内部诊断与复核有各自的结构化输出契约，模型接口和调度器分别检查；内部 `auto_` 任务前缀只用于区分修复预算，正式产物不新增调度字段。
- 完整失败报告、原任务和历史反馈放在文件中供模型读取，不截断报告，也不把越来越长的失败全文反复拼接进提示词。
- 副本隔离和摘要校验用于防止误写污染、过期候选发布；不是操作系统级模型沙箱。校验器只信任新建校验副本中的程序执行结果。
- 修复事件接入现有进度通道，显示策略切换、等待重试和验收结果，不添加界面定时扫描。

每个故障最多三种策略；终稿可由现有 `max_repair_rounds` 限制策略数量。模型操作最多八次（三次修复、三次复核、一次诊断及最多一次诊断协议补正）；明确的超时/限流/暂时不可用返回码仍有最多两次传输重试，等待两秒、四秒且可取消。总调用硬上限为 `8 × (1 + min(worker_retries, 2))`，同时限制反复取消/恢复导致的重派发。诊断补正不重置已经消耗的传输重试额度，也不能把缺失诊断伪造为成功。原生成 worker 的有限重试仍保留，语义修复不再由多层循环相乘。

故障账本位于 `质量治理/自动恢复/<故障标识>/state.json`，记录输入摘要、策略、调用次数、失败反馈和发布状态。重启、外层重新派发、旧重试会话重置均不清空预算；真实输入、模型配置或修复契约变化才创建新一代记录，并归档旧记录。发布后记账前中断时，识别校验阶段预测的结构摘要，补齐提交而不重新调用模型；外部另行修改输入则拒绝覆盖。

全部策略失败时返回 65，保留原产物、候选、诊断及断点，停止当前依赖链，不能无限请求、跳过验收或冒充成功。本版实现常见产物故障自动修复和验收续跑，不承诺任何模型/服务故障都能无人值守完成；未新增后台定时唤醒或外部服务长期故障后的自动恢复守护进程。资料问答和借鉴智能体未在当前仓库独立实现，本轮不宣称已改造这些模块。

## 2026-10-11 误拦截与诊断协议修正

本次实际中断发生在斗破苍穹第 8 章、我独自升级第 7 章的 Delta 阶段。旧内容保全检查按原路径比较，将 41 个字段完整移入详情判为删除，并将质量说明更新判为正文损失；我独自升级末次诊断只返回 `{"difficulty":"easy"}`，旧模型接口仅约束为 JSON 对象，未要求可执行诊断。

- 用 `VALID_FIELDS` 作为位置规则的唯一来源，在程序纠错阶段迁移规范外字段。目标同名但不同值时保留双方并报错，不擅自覆盖；非对象详情不再清空，交原校验器和模型处理。程序不猜测近似名称、不生成缺失提取理由。
- 保全比较使用同一无损迁移规则，对比同一元素同一字段的完整值。更新质量说明时程序保留历史全文并追加当前说明；正文删减仍会被拒绝。命名列表一对一匹配，先保留精确名称对应，再处理纠正名称，不能拿同一个元素抵充两项内容。

## 修复与独立复核材料去重

针对修复器同时要求读取 `failure.md`、`contract.md`，而两者实际都含完整修复包的重复问题，新增每次尝试独立的 `materials.json` 目录。原文、完整章节分析、正式结构、原始失败产物及程序纠错后的参考版本按内容注册；完全相同的全文共用一个材料 ID。不同版本不强行合并，原文件和输出契约均不改写。

导航文档仅将完整且逐字相同、位于整行边界的材料块替换为全文文件引用。处理顺序为最长文本优先；每次改写都执行反向还原断言，不摘要、不截断、不删减正文或要求。原任务中的语义规则、字段约束及未匹配的内容保留。重复的完整反馈转为对同一任务文档的引用；历史反馈先从旧目录无损展开，再转到新副本，避免旧错误误指向当前版本。

修复、诊断和独立复核共用这一份材料目录，各次调用要求同一材料 ID 只读一次。独立复核属于新的模型上下文，仍必须读取原契约和完整事实证据，并非依赖模型跨调用记忆。另提供 `changes.json`，只列程序参考版本与候选之间的变更位置，不再嵌入旧值/新值全文；它只是定位入口，不能替代完整内容与证据复核。复核提示不再继承“执行修复”的策略指令。

同时修正路径转换重复替换的问题：当当前副本已位于项目目录之下时，现有副本路径不再被重复追加一次项目路径。目录、导航文档、历史反馈和变更清单纳入原有只读摘要保护；模型篡改这些文件仍会被拒绝发布，并恢复只读副本，避免下一策略读取已损坏的材料目录或历史引用。

程序优先短路、内容保全、独立复核、调用预算、幂等提交及阶段校验模式均保留。此轮未修改生成提示词、JSON schema 或原校验器：章节仍为 `process`，周期治理仍为 `governance`，终稿仍为 `strict`。
