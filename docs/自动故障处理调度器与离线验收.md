# 自动故障处理调度器与离线验收

本轮在 `1a8fa15` 的事务提交、断点和共享 worker 准入基础上，实现生成产物的自动修复闭环。项目管理 ID：`YH-20260710-002`；开发者：范震。分析内容、章节 Markdown 的十节要求、Delta/治理 JSON 契约和终稿 strict 校验均保留。

## 调度流程

普通生成或提交发现产物错误后，统一进入 `fault_recovery.recover_artifact`。适用入口为章节分析、章节 Delta、周期治理和最终草稿，包括工作台治理/终稿入口。已有确定性纠错仍先执行；能直接通过原校验器的问题不需要请求模型。

1. 为失败产物、原文、章节分析和相关正式结构建立副本，保存原始失败文件。
2. 第一策略定点修复；失败后第二策略重新核对原文证据、正式名称与历史反馈；仍失败则第三策略先独立诊断，再按诊断修复。
3. 每个候选先检查内容保全，再运行原有校验与合并流程。校验运行于重新构造的干净副本，不能使用模型写出的“成功报告”或提交凭据。
4. 程序检查通过后，再单独请求模型复核内容保全、原契约和证据支持。复核结果必须与候选摘要绑定，全部检查通过、问题列表为空且复核期间候选未改动，才允许发布。
5. 发布前核对正式输入是否变化；通过后原子写入产物，由现有幂等提交逻辑发布正式结构并继续流水线。修复提交的章节仍执行原定周期治理，不跳过检查。

第三策略可用环境变量 `ND_RECOVERY_COMMAND` 配置另一个兼容现有 worker 协议的模型命令；未配置时使用当前模型进行独立诊断，不自动购买或选择未授权服务。单纯换策略默认可用，不需要用户逐次确认。

## 内容和故障边界

- JSON 原字段和列表项不可通过删除来规避错误；长叙述保留原文，必要时补充。名称等标识符可纠正。Markdown 保留原有非标题内容行，允许修复标题与补充内容。损坏 JSON 尽可能保留可解析的叙述字符串，再交独立复核。
- 内容保全检查属于保守的机械检查，不等同于语义正确性证明。错误结论须保留追溯并补充有原文依据的纠正说明；模型仍可能判断错误，因此原程序验收和独立复核均不能省略。
- 原生结构化输出继续使用原 Delta/治理 schema。内部 `auto_` 任务前缀只用于区分修复预算，正式产物不新增调度字段。
- 完整失败报告、原任务和历史反馈放在文件中供模型读取，不截断报告，也不把越来越长的失败全文反复拼接进提示词。
- 副本隔离和摘要校验用于防止误写污染、过期候选发布；不是操作系统级模型沙箱。校验器只信任新建校验副本中的程序执行结果。
- 修复事件接入现有进度通道，显示策略切换、等待重试和验收结果，不添加界面定时扫描。

每个故障最多三种策略；终稿可由现有 `max_repair_rounds` 限制策略数量。模型操作最多七种（三次修复、三次复核、一次诊断），每种对明确的超时/限流/暂时不可用返回码最多再试两次，等待两秒、四秒且可取消。总调用预算同时限制反复取消/恢复导致的重派发。原生成 worker 的有限重试仍保留，语义修复不再由多层循环相乘。

故障账本位于 `质量治理/自动恢复/<故障标识>/state.json`，记录输入摘要、策略、调用次数、失败反馈和发布状态。重启、外层重新派发、旧重试会话重置均不清空预算；真实输入、模型配置或修复契约变化才创建新一代记录，并归档旧记录。发布后记账前中断时，识别校验阶段预测的结构摘要，补齐提交而不重新调用模型；外部另行修改输入则拒绝覆盖。

全部策略失败时返回 65，保留原产物、候选、诊断及断点，停止当前依赖链，不能无限请求、跳过验收或冒充成功。本版实现常见产物故障自动修复和验收续跑，不承诺任何模型/服务故障都能无人值守完成；未新增后台定时唤醒或外部服务长期故障后的自动恢复守护进程。资料问答和借鉴智能体未在当前仓库独立实现，本轮不宣称已改造这些模块。
