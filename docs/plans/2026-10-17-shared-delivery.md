# 统一交付编排实施计划

**目标：** 自动全流程和手动收尾共用步骤顺序、前置检查和失败停止逻辑，保留自动阶段断点。

**设计：** 在 `engine/scripts/delivery_workflow.py` 集中声明三个既有交付阶段，提供单阶段执行和按序执行两个入口。自动状态机引用同一阶段序列；手动适配器调用整条交付流程。底层复用现有内容门禁、草稿准备、严格验收、排版及发布函数。

## 约束

- 仅处理交付重复编排，不拆分 run_pipeline，不改变章节、周期、报告和导出调度。
- 保留 `final_pack`、`commit_final_draft`、`finalize` 名称及持久化状态兼容。
- 默认交付零模型调用；历史补齐仍须显式 `repair_history=True`，保留原修复预算和凭据。
- 每个可恢复阶段独立检查内容前置条件；失败原码返回，后续步骤不执行。
- 发布使用原 `cmd_finalize` 内置的严格验收与版本保护。手动入口额外的同内容独立校验并入统一发布步骤，避免重复校验进程。
- 不改 UI、现有书籍、运行配置和公开任务类型；提交遵守项目标签格式。

- [x] 运行相关引擎/后端回归并做独立审查，按项目格式提交。

## 重点审查

1. 状态模块导入工作流时不能形成 run_pipeline 循环依赖。
2. 自动流程中途恢复，仍执行发布前门禁。
3. 手动维护的 timeout/retries/repair_limit 和复核调用保持有效。
4. 任一步失败不得继续发布、丢失原码或标记成功。
5. 移除重复校验后，正式发布仍校验同一份字节并保留版本保护。
