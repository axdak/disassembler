## 合并时补齐的衔接

1. **材料范围与容量拆分**：拆分请求位于深层目录，而原件和已完成结果可能在同级目录。
   宿主生成明确的材料清单，将逻辑原件路径映射到已冻结副本。模型可以完整分页读取这些材料，
   不会因目录隔离读不到证据，也不会改读正在变化的原件。普通故事 JSON 中的任意路径不会自动扩展权限。
2. **流式耗尽识别与受控工具**：保留真实长度耗尽返回容量错误并拆小的逻辑；
   流式分支沿用统一 MCP 配置，不重新开启范围外的文件读取工具。不新增固定八轮上限。
3. **程序纠错与内容保全**：允许有正式索引证据的完整类别迁移；主标签和补充标签按完整内容比较，
   允许去掉同文副本或搬运，删除独有标签、分析正文仍然失败。损坏标签不被当作空内容覆盖。
4. **输出及校验**：没有更换故事或 Delta 输出格式，没有降低章节、周期治理、最终校验的要求。
   程序优先、章节宽松、治理严格、尾段治理、周期简介替换、默认不做全书模型治理和最终严格收尾均保留。

## 统一到 main 与让新版生效

本次只完成隔离整合和提交，**正在运行的软件不会自动切换成新版**。
等当前任务自然结束或在界面安全停止后，退出应用，包括托盘中的进程，再执行以下步骤。
不要在旧应用运行时切换它使用的源码；后续 worker 会从源码启动，可能导致新旧实现混用。

1. 在主目录重新核对未提交文件与上述备份的差异。如果整合之后又有新修改，先保留并单独整合，
   不要把所有新变化都视为已经合入。
2. 备份主目录当时的未提交修改，切换到 main，然后做快进合并：

   ```powershell
   Set-Location 'C:/Users/53519/Downloads/novel-disassembler-desktop'
   git status --short
   git stash push -u -m 'pre-main-integration-preserve-local-work'
   git switch main
   git merge --ff-only codex/recovery-material-dedup
   git status --short
   git log -1 --oneline
   ```

   每一步成功再执行下一步。若不能快进，停止并检查新增分叉，不要强制覆盖。
   `stash` 是原修改的额外备份；已经整合过的部分不要再次 `stash pop`，否则会重复或冲突。
   不删除 stash、旧分支或旧工作区，待新版使用确认后再整理。

3. 从统一后的主目录启动，使用现有 Python runtime 和桌面依赖：

   此启动脚本会处理开发端口上的旧进程，因此必须先退出正在使用的旧版，不要同时启动两份。
   更新源码后仅刷新界面不够，必须重启应用及后端；旧安装包也不会因源码提交自动升级。

4. 继续原项目，不勾选“强制重跑”。已提交章节和正式数据仍保留；未完成节点按已有检查点与校验继续。
