# 第 037 章 Delta 修复耗尽（rc=65）根因诊断

日期：2026-10-13　工程：`拆书暂存/拆书_斗破苍穹`　故障单元：`章节处理/Delta/第037章_第三十七章_萧玉.json`

## 一、结论先行

1. **表面原因**：Delta 有 1 条硬错误 —— `修改元素.角色[萧家] 修改目标[萧家]不存在`。模型把「萧家」（家族/势力）当成**角色**写进了 `修改元素.角色集`，而结构里 `萧家` 只存在于 `地点集` 与 `阵营集`。
2. **真正根因（引擎侧设计缺陷）**：第一轮 `targeted` 策略的**窄修复契约在结构上不可满足**。`delta_repair_scope()` 只给出一个字段 `/修改元素/角色集/6/名称`，并强制 `allowed_values` = 结构里已有的 **30 个正式角色名**。该条目内容讲的是「萧家家族格局」，任何现有角色名都不正确；而补丁协议又**不允许删除、不允许改结构位置**（`value` 必须是非空字符串，`path` 必须与 scope 完全相等）。模型唯一合法的动作都是伪造身份 → 它拒绝 → 补丁不合格 → `worker_failed`。
3. **叠加问题**：第 2、3 轮（`evidence` / `diagnosed`）**在 1.5 秒内即以 rc=65 提前返回，全程没有发起任何模型调用**（无 CLI 会话、无 worker 日志、`state.json` 的 call 无 error）。所以「三种策略都试过了」是假象 —— **实际只有一轮无效尝试**。
4. 综合看：**这不是容量/输出预算问题，也不是模型能力问题，而是「窄修复范围只能改名、无法改归类」与「后两种策略空转」两个缺陷叠加**。

## 三、失败的完整链路

```
validate_delta 报 1 硬错误（修改元素.角色[萧家] 目标不存在）
  → recover_fault：mechanical 程序纠错 0 项（rc=1）
  → index==0 → delta_repair_scope() 只给 /修改元素/角色集/6/名称
       allowed_values = 30 个既有角色名（不含萧家）
  → run_paged_recovery：inspect_pack 超容量 → 建不可变证据索引（6 片，937s）
  → 模型必须只改这一个字段、且值必须落在 allowed_values 内
       改名到任何现有角色名 = 把家族内容挂到个人身上 = 伪造身份（契约明令禁止）
       删除 / 移到阵营集 = 协议不允许
  → 补丁不合格 → worker_failed（rc=65）
  → index==1/2 → 复用共享证据索引时**提前返回 REPAIR_EXHAUSTED**（1.5s，无模型调用）
  → 全部策略用尽，status=exhausted，保留断点与证据
```

`run_paged_recovery` 末尾是可疑的第二处缺陷：

```python
return rc if (not changed and tree.unchanged()
              and all(digest(path) == signature for path, signature in indexed_signatures)
              and (shared_tree is None or shared_tree.unchanged())) else REPAIR_EXHAUSTED
```

任何一项完整性判据为假，直接返回 `65`，且**不写 `call["error"]`**，外部只能看到「策略耗尽」，无法区分「模型改坏了」和「索引复用校验不过」。
`_immutable_recovery_index()` 中另有 `raise TreeFailure(REPAIR_EXHAUSTED)`（行 319 / 330，以及 `bounded_generation.py:46`）。

## 五、引擎侧待修建议（按优先级）

1. **扩展窄修复契约的表达力**：当错误是「修改目标不存在」且该名称在**其它集合**中存在同名片时，scope 应允许「重定位/移除该条目」，或直接把 scope 判为不可窄修、跳过 `targeted`、直接进入全量重写策略。当前 `delta_repair_scope` 的注释写着 *never guess values*，但它给出的唯一出路本身要求猜一个值。
2. **让 `run_paged_recovery` / `_immutable_recovery_index` 的提前返回带上原因**：设置 `call["error"]`（例如 `"不可变证据索引复用校验失败"`），否则「策略耗尽」无法与「模型没干活」区分。
3. **澄清「三轮策略」的真实性**：第 2、3 轮若因基础设施原因未执行，不应记账为「已尝试过该策略」，否则重跑会永远从同一断点空转。
4. **提示词侧**：`角色集` 只应放**人物**；家族/势力→`阵营集`，场地/建筑→`地点集`，器物→`物品集`。本章同类误分类还有 `巨木台`（当作新增角色，目前只是软警告）。
