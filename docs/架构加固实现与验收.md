# 架构加固实现与验收

基线提交为 `72c8e7a`，在上一版治理契约、名称匹配与治理事务修复之上实施。目标是降低重复执行、让中断可恢复、减少界面扫描；不降低分析质量要求，不修改最终分析文档和故事结构的交付格式。

## 实现范围

| 问题 | 本轮处理 | 恢复边界 |
| --- | --- | --- |
| 普通章节先修改正式结构，再尝试回滚 | 合并、规范化、标签处理、校验、差异记录全部对候选文件执行；全部成功后原子替换 | `.commit.json` 保存产物摘要；发布前中断重做本地提交，发布后中断补齐进度，不重复合并 |
| 终稿修复的外层、内层重试相乘 | `repair_final` 进入统一修复预算；流水线与工作台均传入相同总额度；耗尽返回 65，外层停止再派发 | 用户明确继续或重试开启新额度；保留草稿和修复历史，不从整本书重做 |
| 后续分包失败后重新请求前面成功的分包 | 成功分包按完整任务内容、结构内容、命令、相关环境配置、模板与 worker 版本保存检查点 | 摘要和产物完整性匹配才恢复；失败或损坏不能命中；工作台“强制重跑”绕过复用 |

| 每次找下一章都解析已验证的大快照 | 缓存成功验收结果，文件路径、大小、修改时间或创建时间发生变化即失效 | 首次和文件变化后仍执行验证；缓存仅在进程内，不替代磁盘证据 |
| 长等待没有反馈，结束前日志未保存 | 隐藏 worker 每 30 秒报告存活和已等待时长，收到的输出即时追加到日志 | 表示进程尚未结束，不冒充模型 token 进度；模型提供方自身仍可能超时或失败 |
| 全书任务截掉过长章节分析的尾部 | 保留完整章节分析；全书任务按实际渲染长度拆连续材料片段，重复完整输出契约 | 片段拼接覆盖原材料；契约/索引本身占满预算时保留完整材料并明确报错，不通过删减内容继续 |

提交凭据和分包缓存只作为内部恢复材料，位于现有项目目录；正式故事 JSON 和分析 Markdown 不新增内部控制字段。历史没有提交凭据的章节继续按原验收规则读取。恢复凭据的 `published` 只在进度更新之后置为真，避免进度保存失败后被误跳过。

## 验收方式

全程使用本地假 worker、临时项目和故障注入，没有调用真实模型，没有重新运行《斗破苍穹》或《我独自升级》。此前两本书失败数据的离线验证结论见《治理可靠性修复与离线验证》。本轮没有重新修改书籍目录。

新增测试覆盖：五个本地提交步骤失败、正式结构发布前后中断、进度保存中断、快照缓存失效、终稿传输重试的总预算、工作台终稿入口、两个 worker 入口共享并发上限、排队取消和异常释放、成功分包复用与损坏/输入变化/强制重跑失效、失败分包不复用、长分析全文覆盖、worker 返回前日志已落盘、刷新突发事件的合并及无事件时不轮询。

旧分包测试原先使用 50 字符总预算，无法容纳完整契约，现改用足量材料和可用预算验证实际分包。并发集成测试增加等待执行线程进入的同步条件，不再将数据库中的 `running` 标记当成线程已经进入适配器的证明。

最终结果：引擎完整回归 347 项、后端完整回归 182 项、桌面回归 36 项全部通过，共 565 项。Web/Node TypeScript 检查和 Electron/Vite 构建通过。后端仍有原有 Starlette/httpx 的弃用提示，不影响测试结果。

## 适用范围与剩余边界

保留现有 Electron + Python + SQLite 的单体分层结构，没有增加微服务或消息中间件。本轮主要补强事务、有限重试、检查点、准入和事件刷新，不能据此承诺模型不会输出错误，也没有进行真实模型延迟基准测试。

全书汇总仍使用现有 reduce 流程，超大规模 partial 汇总的分层归并需要单独设计。原文抽样配置、其他背景材料的既有摘要策略没有改为新的内容删减策略；本轮解决的是章节分析正文截断及全书材料分包。单章结构/视觉任务的独立分层拆分、跨应用进程的并发协调不在本轮实现范围。

当前仓库没有独立的资料问答、借鉴智能体实现；本轮共享 worker 机制可以复用，但不宣称已经改造这些不存在的模块。代码测试与桌面构建不等于已经重启、安装或运行实际书籍任务。

## 2026-10-11：容量与治理分阶段加固

此节记录后续增量改造，前面的测试数量为当时的历史记录。

1. 统一请求容量预检：完整已声明材料去重计量，保留容量报告；超过预算返回 64，不截断证据，也不重复执行同一请求消耗语义修复策略。CLI 内部后续工具读取仍无法完整观测，报告明确标注估算而非真实 token 用量。
2. 单章局部修复：程序规范化先行；缺失提取理由与已确诊的名称错误可由模型只返回字段补丁。程序限制可写路径、校验原件摘要，再执行原有完整校验与独立复核。普通章节与治理仍使用各自原有验收模式。
3. 周期治理：按容量拆连续区间，子区间通过后再做跨区间复核；不能把子区间通过等同于父区间完成。重放时先应用子区间，再应用父区间的跨区间补丁。
4. 全书终稿：完整原文、分析、Delta、治理修正及故事结构进入材料目录；完全相同的文件共用一份读取材料，但保留来源角色。超大任务分批读取，模型输出现有治理 Delta，由程序合并到私有候选。真实结构修改须独立复核，最后仍执行原有严格终稿校验；全部通过才原子替换草稿。

### 容量配置

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `ND_CONTEXT_INPUT_TOKENS` | 300000 | 输入上限 |
| `ND_CONTEXT_OUTPUT_TOKENS` | 20000 | 输出预算；CodeBuddy 显式输出请求不得超过它 |
| `ND_CONTEXT_CONTEXT_TOKENS` | 300000 | 输入与输出共享窗口；只有提供方明确独立计量时才设为 0 |
| `ND_CONTEXT_RESERVE_TOKENS` | 30000 | 系统提示、工具和估算误差的预留 |

默认已知输入可用预算为 250000 token。这里使用保守字符估算，没有冒充模型 tokenizer；预留也不能保证任意 CLI 工具循环都不溢出。后续若需要逐次工具调用的硬容量控制，应单独接入能够提供用量和会话事件的运行时，而不是取消业务校验。

### 恢复与验收边界

终稿分步治理保存材料覆盖区间、每步尝试次数、已验收快照及最终发布凭据。材料、提示契约、相关代码或模型配置改变会使旧会话失效；取消不消耗语义修复次数。每步最多三次尝试，严格校验失败不能重置预算或覆盖正式草稿。原文来源在发布前再次核对摘要，避免覆盖并发编辑。

使用已有失败数据与已有修复候选离线验证：《斗破苍穹》先由程序归位 41 处字段，再局部补齐 11 条缺失理由；《我独自升级》仅修正 1 个已确诊名称。两例均通过原有 Delta 校验与内容保全检查。全书回放使用模拟“无需修改”输出，验证严格拒绝、全文材料覆盖及再次运行不重复请求；这不代表已经验证真实模型的全书语义质量。没有重新运行两本书或请求真实模型。

本轮引擎完整回归 436 项、后端完整回归 183 项通过；最终容量报告入口调整后，终稿治理 14 项针对性测试再次通过。后端保留原有 Starlette/httpx 弃用提示。额外覆盖合法合并后的档案保全、历史材料篡改恢复、严格失败不发布、模型/契约变更使检查点失效、程序规范化先于模型重试。

## 超大单章与全书报告的容量分层

### 职责与数据保全

`capacity_tree.py` 负责连续材料分片、节点检查点、容量自适应与有限重试；`bounded_generation.py` 对接章节分析、章节 Delta、修复材料和报告汇总。章节理解与结构化提取仍为两个独立步骤，最终依旧由原有章节提交与治理入口校验，不能用树节点通过替代业务校验。

- 单章内部片段仍属于原章节；程序合成一个十节分析 Markdown 和一个原格式 Delta，不增加虚假章节，不改变五章治理边界。
- 历史故事结构及最近十章完整 Delta 全文保留，超限时分批阅读并形成有来源位置的关联索引。索引服务于跨片判断，不能替代原件作为事实证据。
- 单章及报告的叶子正文完整保留，上层只增加跨区间判断，最终由程序按标题层级或原 JSON 结构合成；不会反复用短摘要替换已有正文。
- 正式名称相同的元素才确定性合并。只有本章明确新增的同名条目，才允许吸收其他片段对该新元素的修改；未知修改名称继续交原校验器，不能把拼写错误偷偷转为新增元素。
- 字符串正文和证据保全；不能直接合并的元数据标量由模型只裁决该字段，原值与依据保留在内部记录，禁止程序无依据覆盖。
- 全书汇总按目标文件分别组织，所有候选通过现有格式检查、输入版本核对后才逐个原子发布。中断后复用已完成的树节点；这不等于跨多个文件的一次文件系统事务。

### 调度与恢复

普通材料仍走现有路径。声明了分层材料的全书任务，在输入超限或预计单次输出风险较高时进入树；章节分析/Delta 超限时进入单章树。提供方返回 64 时保留容量语义，不再误报用户取消；130 才是取消。

容量错误才继续二分原材料，超长不完整 JSON 也保留原响应后尝试缩小片段。普通协议/语义错误每个节点最多三次，逐次改变修复指导；第三次可使用已有 `ND_RECOVERY_COMMAND`。节点预算、成功摘要和拆分决定持久化，重启不重置次数。传输异常不触发无限分片。父任务在 worker 并发准入之外选择分层路径，避免父任务占住名额再等待子任务。

超大的修复/复核材料先独立分页组织，再执行原来的限定修复和独立复核；程序优先、可写字段限制、内容保全和发布前版本核对保持有效。分层概览、覆盖区间、重试记录和原始失败响应仅是内部材料，不进入正式 Markdown/故事 JSON。

### 本轮离线验收与限制

使用两本书已经保存的第 7/8 章原文、分析、失败前故事结构和既有修复候选，模拟模型返回候选分片。合成 Delta 通过原 process 校验与原候选内容保全检查；再次执行已完成节点没有新增模拟请求。已有章节分析经分层合成仍通过十节结构校验，正文和表格逐行保留；报告回放同样核对原分析的全部非空行。没有调用真实模型，也没有重新运行书籍任务。

自动化测试还覆盖全文连续区间、跨层恢复、JSON/Markdown 格式、元数据冲突裁决、未知修改名称、容量返回码、原件保护、失败预算不重置、多目标失败不提前发布和修复材料分页。治理回滚集成用例显式选择 manual，仅检验真实程序回滚，不再等待离线防护拦下的提供方恢复尝试。

本轮引擎完整回归 446 项、后端完整回归 183 项通过；随后新增及调整的容量/故障恢复/提供方协议专项 85 项、检查点专项组合 31 项、最终容量与任务包/章节范围专项 43 项通过（这些专项彼此有重叠，不累加为独立测试总数）。后端仍有原有 Starlette/httpx 弃用提示。

容量树增加的是在受限窗口内继续处理的能力；超大任务可能需要更多模型调用，尚未测量真实延迟与语义质量。CLI 内部工具读取用量仍不可精确观测。若最小契约加运行开销都装不下，或模型连续输出不合格、服务持续不可用，仍会保留检查点并停止；不会通过删除内容、降低标准或无限重试冒充完成。

## 统一模型容量设置与任务隔离

设置页新增输入上限、单次输出上限、总上下文窗口、安全预留（均为 Token），以及单次调用超时（秒）、失败重试次数。字符分包参数保留并明确单位，不再以“上下文预算”混称模型窗口。默认输入 300000、输出 20000、共享窗口 300000、安全预留 30000，可用输入为 250000。公式为 `min(输入上限, 总窗口 - 输出上限) - 安全预留`；总窗口为 0 仅表示提供方明确拥有独立输入和输出额度，此时为 `输入上限 - 安全预留`。

前端实时预览并阻止保存空值、非整数或无可用输入的组合；后端将局部更新与已保存值合并校验，在同一数据库锁和事务内保存。任务不会读到一半新、一半旧的配置。配置固定于任务开始，运行期使用上下文变量，章节并发线程显式继承；内部打包脚本和模型子进程接收独立环境副本，不修改共享进程环境。已启动任务不受保存设置影响，全流程队列保留入队时配置；工作台尚未启动的任务在开始时读取快照。不同容量使报告检查点失效，避免复用不符合新策略的结果。

超时和调用失败重试沿用原有参数传递；零重试仍可保存，表示首次调用之后不做该层重试。语义恢复、分层节点与最终治理有自己的持久化有限策略预算，继续保持单一重试负责人，不把调用重试与语义重试相乘。小容量触发既有分层入口，不改正式产物格式，也不修改宽松章节校验与严格治理校验。

### 各阶段实际上读取什么

| 阶段 | 上下文组成 | 大材料处理及边界 |
| --- | --- | --- |
| 章节分析 Markdown | 本章完整原文、分析要求、十节格式约束 | 超大单章连续分片，保留叶子正文并由程序合成原格式；常规分析并不附加全部历史故事 |
| 章节 Delta | 本章原文、本章完整分析、故事历史、正式名称及输出契约 | 小故事内嵌全文；大故事常规路径使用完整名称索引、最近十章完整 Delta 和完整故事文件入口。超限路径分页阅读历史形成来源索引，再处理本章；索引不是历史正文的等价替代 |
| 每五章治理 | 当前周期完整原文、分析、Delta，上次治理记录、分类体系、历史故事 | 先尝试全故事，随后改为名称索引加相关档案、名称索引；周期证据不截断。仍超限则按章节区间拆分，子区间完成后做跨区间复核。最小单章治理包仍放不下时会明确失败，不能宣称任何窗口都能继续 |
| 全书分析及报告 | 故事名称索引、目标档案、各任务规定的章节分析/Delta 或全书结构材料、输出契约 | 先分包分析，再按目标文件逐层汇总；保留叶子结果和上层新增判断，程序合成完整产物。结构类任务使用故事结构/梗概等全书资料及文件入口，不等于每种报告都重新通读全部章节原文 |
| 最终全书治理 | 隔离候选故事、完整材料副本、分片证据、全局名称索引、已接受修改和严格整理要求 | 分步补丁与局部复核后再做全局一致性复核、原严格终稿校验；成功才允许发布 |
