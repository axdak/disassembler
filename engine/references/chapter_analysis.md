# 章节分析规则

章节分析器负责完成当前章节的文学理解，重点提取梗概、人物、冲突、增量信息、伏笔、情绪点，以及章节通俗功能、事件分组和画面价值候选。

**核心准则：**
1. 每次**只能处理一个原文切片**（对应 `_索引.json` 的一个 seq）。
2. 只输出 Markdown 分析报告，**不允许输出 JSON 或合并全局结构**。10个固定章节必须完整保留；原文没有明确内容时写“本章无明确新增”并说明依据，不能删除章节。
3. 对本章出现的事件，必须先在第8节列出本章事件脊线与剧情段覆盖范围，再生成统一分组建议：`8位段号-40字以内复合剧情段短名`，短名需压缩包含剧情、剧情线主题、叙事功能、爽点/情绪点、冲突悬念类型。连续事件仅在本章内复用同一分组短名；不做跨章节分组承接，段号由合并脚本统一生成。
4. 第8节还要为每个事件给出四维复合标签建议，格式固定为 `剧情线主题+叙事功能+爽点/情绪点+冲突悬念类型`，例如 `侠之真义+主题点化+感动+观念冲突`。该标签不写段号、不写剧情段名、不带冒号，后续 Delta 应放入事件 `标签集` 并保留供界面直读。
5. 画面资产评估要客观，不强行补充原文没有的画面要素。

## 使用说明
执行章节分析任务时，请读取 `prompts/chapter_analysis.j2` 模板，将其应用到当前切片原文上，并将结果保存至 `章节处理/第N章_<标题>.md`。

在交接 Delta 前，`validate_chapter_analysis.py` 会机械校验标题、10个章节、非空内容、最低总长度，以及第9节的候选表或“无高价值画面候选”声明。若不通过，流程会生成 `task_chNNN_analysis_regenerate.md`；智能体必须忽略旧MD、重新阅读原文并覆盖生成完整MD，不会进入 Delta 阶段。
