# 最终结构整理与强校验 (步骤 4)

**目标**：从过程型 `故事结构_增量.json` 生成最终交付型 `故事结构.json`。

## 重要原则

`故事结构_增量.json` 是过程数据库，不要求文学整理质量完美，但必须始终满足：

```text
1. JSON格式合法
2. schema合法
3. 关键字段完整
4. 全量过程库在 process 模式下校验通过；本切片触碰元素数量可追踪
5. 来源章节可追踪
6. 不允许无依据覆盖旧事实
```

`故事结构.json` 是最终交付文件，必须完成：

```text
1. 顶层只能包含：介绍、角色集、事件集、地点集、线索集、阵营集、物品集，以及可选的其他事项集
2. 介绍只能包含：标题、描述
3. 所有元素只能包含本规范定义的标准字段 + 公共字段
4. 非标准信息必须放入详情，不允许出现在元素顶层
5. 详情 key 不可包含标点、空格或下划线
6. 详情 value 只能是 string 或 string[]，但 string 可写长文本，应完整承载档案信息
7. 详情数组必须全部是 类型:名称 的元素引用
8. 标准交叉引用必须指向元素正式名称，不使用别名作为引用目标
9. 全局去重、别名合并、路人降级或清理
10. 事件粒度统一、伏笔和线索归类、人物关系统一
11. 地点/阵营层级整理、分组统筹
12. validate_structure.py --strict 强校验通过
```

注意：本 skill 是拆书，不是凭空创作。结构示例中的角色名、事件名、地点名等仅为格式说明，不得出现在实际输出中；所有元素必须来自原文或有证据的质量治理结果。数量要求在最终创作型交付中可强制，但拆书提取时不得为了达标编造原文不存在的元素。

## 最终执行流程

> **推荐使用 `run_pipeline.py` 自动化命令**，而非手动执行以下步骤。详见 `commands_and_resources.md` "主控器运行方式"章节中的"最终整理与交付"部分。

1. 复制过程JSON为草稿基础：

```bash
cp <项目目录>/故事结构_增量.json <项目目录>/故事结构_草稿.json
```

2. 运行全量验证：

```bash
python scripts/validate_structure.py <项目目录>/故事结构_草稿.json > <项目目录>/质量治理/最终审计/validate_report.txt
```

3. 调用最终结构整理器，输入：

```text
故事结构_草稿.json
validate_report.txt
全书分析/剧情结构/章节梗概汇总.md
全书分析/人物分析/人物档案.md
全书分析/剧情结构/伏笔追踪.md
质量治理/周期审计/*.md
质量治理/周期审计/*correction*.json
```

4. 最终结构整理器输出 `故事结构_草稿.json` 的修正版，重点处理：

```text
交叉引用缺失
数量不足
重复元素
别名合并
路人降级
事件粒度不统一
伏笔/线索泛化
详情字段不规范
字段类型错误
分组不合理
旧设定矛盾
```

5. 重复执行验证-修正循环，直到通过：

```bash
python scripts/validate_structure.py --strict <项目目录>/故事结构_草稿.json
```

`--strict` 是最终硬卡口：任何缺字段、额外字段、字段类型错误、机器详情字段不合规、引用不存在、重复名称、父级循环、数量不足、介绍/分组/标签缺失，都会导致交付失败。普通档案详情 key 可以为保真保留少量标点，但会产生质量 warning；详情 value 不做短文本限制，应尽量保留完整档案信息。

6. 通过后输出：

```bash
cp <项目目录>/故事结构_草稿.json <项目目录>/故事结构.json
python scripts/progress_manager.py complete <项目目录> 4
```

最终 `故事结构.json` 必须严格符合 `references/story_structure_spec.md`。
