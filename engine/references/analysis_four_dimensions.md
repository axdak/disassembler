# 拆书向四维度分析规范

本规范定义拆书场景下的宏观/微观分析维度：**世界观 / 设定 / 剧情线 / 大纲 / 细纲**（扩展为五维度）。

> 核心原则：这是**从原文中提取/反推**，不是凭空创作。所有结论必须能回指章节号、原文片段、章节分析或 `故事结构_增量.json` 元素。不确定写"待确认"，不允许为了完整性编造。

## 与现有分析任务的关系

| 维度 | task 名 | 与现有任务的关系 |
|---|---|---|
| 世界观 | `worldview` | 新增。从原文提取时代背景、地理、制度、势力、历史等宏观环境，区别于 `characters`（人物） |
| 设定 | `settings` | 新增。从原文提取修炼体系、功法武技、特殊种族、职业、法宝、规则等微观运行机制 |
| 剧情线 | `plotlines` | 新增。`plot` 是事件层（剧情线索/伏笔/冲突），`plotlines` 是线索层（主线/支线/暗线/成长线/情感线的分类、起承转合、交汇） |
| 大纲 | `outline` | 新增。反推原文的卷/篇章级叙事框架 |
| 细纲 | `detailed_outline` | 新增。反推原文的章节/场景级结构 |

## 引用机制

四维度分析报告**不引入新的编号体系**，直接复用 `故事结构_增量.json` 已有元素的 `类型:名称` 格式：

```text
阵营:玄天宗          → 故事结构.阵营集 中的元素
角色:林婉            → 故事结构.角色集 中的元素
事件:入门试炼        → 故事结构.事件集 中的元素
地点:青云山          → 故事结构.地点集 中的元素
线索:血契觉醒        → 故事结构.线索集 中的元素
物品:天命玉佩        → 故事结构.物品集 中的元素
```

报告中引用原文证据时用章节号：`第0043章` 或 `0043-0045`。

## 维度一：世界观（worldview）

### 目标

从原文中提取作者构建的世界观要素，梳理各要素之间的关联，输出结构化的世界观档案。

### 输出

`全书分析/世界观/世界观档案.md`

### 提取要素表

| 要素 | 字段 | 说明 | 原文证据要求 |
|---|---|---|---|
| 时代背景 | 时代名称、时间跨度、社会阶段 | 故事发生的宏观时代 | 至少 2 处原文证据 |
| 地理环境 | 主要区域、地形、气候、方位关系 | 故事发生的空间舞台 | 引用 `地点集` 元素 + 原文描写 |
| 社会制度 | 政治体制、阶级结构、法律/宗法 | 社会运行规则 | 原文中的制度描写或事件体现 |
| 势力格局 | 主要势力、实力对比、敌友关系 | 力量分布 | 引用 `阵营集` 元素 + 事件证据 |
| 历史纪年 | 纪年方式、重大历史事件、时间线 | 故事世界的历史纵深 | 原文中的历史叙述 |

### 自洽性检查

提取后必须检查并标注：

```text
1. 势力格局是否有闭环？（每对敌友关系是否有事件支撑）
2. 地理是否支撑势力分布？（势力座落地点是否合理）
3. 历史纪年是否与事件时间线一致？
4. 社会制度是否存在不合理冲突？
```

### 上下文优先级

```text
地点集 + 阵营集 > 章节分析MD中的世界观描写 > 原文抽样（含设定密集章节） > 本章Delta
```

## 维度二：设定（settings）

### 目标

从原文中提取作者构建的具体运行规则、能力体系和特殊事物，输出结构化的设定档案。

### 输出

`全书分析/世界观/设定档案.md`

### 提取要素表

| 要素 | 字段 | 说明 | 原文证据要求 |
|---|---|---|---|
| 力量体系 | 修炼等级、魔法系统、能量来源、代价规则 | 超自然/特殊能力的运行逻辑 | 原文中的体系描写 + 角色使用证据 |
| 功法武技 | 功法名称、品级、效果、使用者 | 具体的技能与功法 | 原文使用或介绍证据 |
| 特殊种族 | 种族类型、特征、天赋、弱点 | 非人类种族或特殊血脉 | 原文描写 |
| 职业体系 | 炼药师、阵法师等副职业等级 | 特殊生活或战斗职业 | 原文证据 |
| 物品法宝 | 重要物品、品级评定、特殊效果 | 神器、异火、灵药等设定 | 引用 `物品集` 元素 + 原文证据 |
| 世界规则 | 特殊规则、禁忌、天道/法则 | 世界运行的底层规则 | 原文中的规则描写 |

### 自洽性检查

提取后必须检查并标注：

```text
1. 力量体系是否有明确的代价/限制？（无代价需标"待确认"）
2. 功法/物品的品级体系是否存在前后矛盾？
3. 特殊种族/职业的设定是否在后续剧情中被遗忘（疑似孤立）？
4. 世界规则是否有逻辑漏洞？
```

### 上下文优先级

```text
其他事项集 + 物品集 > 章节分析MD中的信息增量 > 原文抽样（含设定密集章节） > 本章Delta
```

## 维度三：剧情线（plotlines）

### 目标

识别原文中的各类剧情脉络，区分主线/支线/暗线/成长线/情感线，梳理每条线的起承转合节点和交汇点。

### 输出

- `全书分析/剧情结构/剧情线总表.md`
- `全书分析/剧情结构/剧情线交汇矩阵.md`

### 剧情线分类

| 类型 | 代码 | 定义 | 识别特征 |
|---|---|---|---|
| 主线 | MAIN | 贯穿全书的核心剧情 | 贯穿全书、决定结局走向 |
| 支线 | SUB | 主线分叉或独立的次要剧情 | 有独立起止、影响有限 |
| 暗线/伏笔线 | DARK | 隐藏的、后期才显现的剧情线 | 早期表现为细节/伏笔 |
| 角色成长线 | GROW | 角色的能力/心态/认知变化轨迹 | 跟随特定角色 |
| 情感线 | EMO | 角色间的情感发展脉络 | 感情/羁绊/仇恨的变化 |

### 剧情线总表结构

每条剧情线一行：

| 字段 | 说明 |
|---|---|
| 线编号 | `PL-MAIN-001`、`PL-SUB-002`、`PL-DARK-001` 等 |
| 类型 | MAIN/SUB/DARK/GROW/EMO |
| 线名 | 用原文要素命名，如"主线·血契觉醒" |
| 涉及角色 | `角色:名称` 列表，引用 `角色集` |
| 涉及事件 | `事件:名称` 列表，引用 `事件集` |
| 涉及线索 | `线索:名称` 列表，引用 `线索集` |
| 起 | 起点章节 + 触发事件 |
| 承 | 发展章节 + 关键事件 |
| 转 | 转折章节 + 转折事件 |
| 合 | 收束章节 + 结局事件 |
| 优先级 | P0（核心）/ P1（重要）/ P2（次要） |
| 推进节奏 | 集中推进/间歇推进/贯穿全程 |
| 证据章节 | 章节号范围 |

### 交汇矩阵

行列为各剧情线，单元格标注交汇章节和交汇事件：

```text
           PL-MAIN-001  PL-SUB-001  PL-DARK-001  PL-GROW-001
PL-MAIN-001    -          0043章       0080章       贯穿
PL-SUB-001   0043章       -           待确认        0050章
...
```

### 上下文优先级

```text
线索集 + 事件集 > 章节梗概汇总 > 章节分析MD > 原文抽样 > 本章Delta
```

### 与 `plot` 任务的区别

- `plot`：事件层——"发生了什么事件，埋了什么伏笔，谁和谁冲突"
- `plotlines`：线索层——"这些事件构成几条线，每条线怎么起承转合，线之间怎么交汇"

推荐先跑 `plot` 再跑 `plotlines`，但也可独立执行。

## 维度四：大纲（outline）

### 目标

反推原文的卷/篇章级叙事框架，还原作者的宏观结构设计。

### 输出

`全书分析/剧情结构/全书大纲.md`

### 卷级总表

| 字段 | 说明 |
|---|---|
| 卷号 | 第N卷/第N篇（按原文实际分卷，无分卷则按章节区间归并） |
| 章节范围 | 起止章节号 |
| 卷名 | 用原文卷名或归纳命名 |
| 核心冲突 | 本卷的主要矛盾，引用 `事件集` |
| 关键转折 | 本卷的转折点事件 |
| 高潮事件 | 本卷的高潮，引用 `事件集` |
| 结局走向 | 本卷结局及衔接下一卷的方向 |
| 主要角色出入场 | 本卷新登场/退场角色，引用 `角色集` |
| 重要设定/道具引入 | 本卷引入的关键设定或道具，引用 `物品集` |
| 伏笔操作 | 本卷埋设/回收的伏笔，引用 `线索集` |

### 反推规则

```text
1. 优先尊重原文的分卷/分篇标记（如有）。
2. 原文无分卷时，按核心冲突变化划分篇章边界，每篇覆盖一个连续章节区间。
3. 卷边界必须有明确的冲突转换或场景转换作为依据，不能按固定章节数机械切分。
4. 每卷的核心冲突必须能在 事件集 中找到对应事件链。
5. 角色出入场必须有 首次章节/最近章节 证据。
```

### 上下文优先级

```text
章节梗概汇总 > 事件集（按分组/涉及章节排序）> 线索集 > 章节分析MD > 原文抽样
```

### 推荐依赖

`summary` → `outline`（先有梗概才好归并卷级结构）

## 维度五：细纲（detailed_outline）

### 目标

反推原文的章节级甚至场景级结构，还原作者的微观叙事设计。

### 输出

`全书分析/剧情结构/章节细纲.md`

### 章节级细纲表

每章一行：

| 字段 | 说明 |
|---|---|
| 章节号 | 固定宽度，如 `0043` |
| 章节标题 | 原文标题 |
| 场景列表 | 本章包含的场景（用 `—` 分隔） |
| 出场人物 | 引用 `角色集` |
| 章节目标 | 本章要达成的叙事目的 |
| 核心冲突 | 本章的具体冲突 |
| 关键事件 | 引用 `事件集` |
| 伏笔操作 | 埋设/暗示/回收，引用 `线索集` |
| 章节钩子 | 本章结尾的悬念/钩子 |
| 氛围基调 | 本章的情绪/氛围 |
| 字数 | 原文实际字数 |
| 推进剧情线 | `PL-xxxx-xxx` 列表，引用剧情线总表 |

### 场景级细纲表（可选，针对关键章节）

| 字段 | 说明 |
|---|---|
| 场景编号 | `CH0043-S01` |
| 所属章节 | `0043` |
| 时间 | 场景内时间 |
| 地点 | 引用 `地点集` |
| 出场人物 | 引用 `角色集` |
| 场景冲突 | 本场景的具体冲突 |
| 场景功能 | 铺垫/推进/转折/收束/过渡 |
| 原文证据 | 章节号 + 原文片段位置 |

### 反推规则

```text
1. 章节级细纲覆盖全部已分析章节，不能跳章。
2. 场景级细纲只针对关键章节（高潮/转折/重要伏笔章节），不要求全覆盖。
3. 场景划分以时间/地点/视角变化为界。
4. 章节钩子必须是原文实际存在的悬念，不能编造。
5. 字数填原文实际字数，不估算。
```

### 上下文优先级

```text
章节分析MD（10维度）> 章节梗概汇总 > 事件集 + 线索集 > 原文抽样 > 本章Delta
```

### 推荐依赖

`summary` + `outline` → `detailed_outline`（先有梗概和卷级结构，再做章级细纲）

## 四维度之间的联动

四维度通过 `故事结构_增量.json` 的元素引用实现联动，**不引入额外编号**：

```text
世界观（worldview）
  └─ 引用：阵营集、地点集、物品集
  └─ 输出：世界观档案.md

设定（settings）
  └─ 引用：其他事项集、物品集、角色集
  └─ 输出：设定档案.md

剧情线（plotlines）
  └─ 引用：事件集、线索集、角色集
  └─ 输出：剧情线总表.md、交汇矩阵.md
  └─ 细纲的"推进剧情线"字段引用剧情线编号

大纲（outline）
  └─ 引用：事件集、角色集、线索集、物品集
  └─ 输出：全书大纲.md
  └─ 细纲的章节归并参考大纲的卷级划分

细纲（detailed_outline）
  └─ 引用：事件集、线索集、角色集、地点集
  └─ 引用：剧情线编号（PL-xxxx-xxx）
  └─ 输出：章节细纲.md
```

当 `故事结构_增量.json` 被治理修正（如角色合并、事件重分类、线索整理）后：

```text
受影响的维度 → 需要刷新的报告
角色合并/重命名 → characters、plotlines、outline、detailed_outline
事件重分类/合并 → plot、plotlines、outline、detailed_outline
线索整理 → plot、plotlines、detailed_outline
阵营调整 → worldview、characters
地点调整 → worldview、detailed_outline
```

## 推荐执行顺序

```text
summary → characters → plot → worldview → settings → plotlines → outline → detailed_outline → report
```

其中：
- `worldview` 建议在 `characters` 之后（人物档案提供势力归属信息）
- `settings` 建议在 `worldview` 之后（宏观世界铺垫后梳理微观设定）
- `plotlines` 建议在 `plot` 之后（先有事件层分析再做线索层梳理）
- `outline` 建议在 `summary` 之后（先有梗概才好归并卷级结构）
- `detailed_outline` 建议在 `outline` 之后（先有卷级框架再做章级细纲）
- `report` 始终最后

## 质量要求（复用全书分析通用规则）

```text
1. 结论必须能回指章节号、原文片段、章节分析或故事结构元素。
2. 不确定的信息必须写"待确认"，不能写成事实。
3. 不允许为了完整性补不存在的人物关系、伏笔、阵营或冲突。
4. 长篇必须先分包再汇总，不允许一次性让模型读全书。
5. 当故事结构JSON被治理修正后，相关分析报告应可局部刷新。
```

## 扩展:故事结构维度
