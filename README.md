# Novel Disassembler Desktop

独立 Windows 工作台，封装并扩展 novel-disassembler 引擎，实现一键拆书全流程
（章节分析、Delta、治理、全书分析、最终整理、导出）。

设计文档见 [DESIGN.md](DESIGN.md)。

## 引擎

`engine\` 是从上游 `novel-disassembler-v12\novel-disassembler`（基线 `dba0213`）
一次性复制的源码副本，为本项目自有代码，可自由修改扩展。基线记录见
`engine\UPSTREAM_BASELINE`。上游不再自动同步。

## 运行时

`runtime\venv\` 是隔离的 Python 虚拟环境（jinja2、json-repair）。开发期用于校验
与运行引擎；正式打包（里程碑4）将替换为随包分发的 embeddable Python。

### CodeBuddy Worker 的材料边界

CodeBuddy 继续按智能体任务包运行，路径上下文通过本项目的只读 MCP 工具
`list_context` / `read_context` 获取。每次启动仅提供任务包、已有目标产物及任务包引用的
书籍项目内文本材料的冻结副本；不提供项目源码、额外目录、命令执行或文件修改工具。
大文件通过 `next_offset` 分页读完。Worker 在临时目录启动，关闭继承的项目设置、
插件和 hooks，仅保留用户所选模型；该限制适用于 CodeBuddy，Agy 保持原有接入方式。

容量拆分和自动修复由宿主额外声明确切的冻结材料清单。分片目录之外的原件路径会映射到
对应冻结副本，已完成结果和材料目录也可按需读取，不扩大到任意父目录或实时原文件。
程序生成的材料目录可继续定位完整证据，故事正文中的任意路径不自动成为读取权限。

单文件内容从输出捕获，多文件内容通过精确路径映射的结构化输出返回，宿主校验后保存。
`ND_CODEBUDDY_ARGS` 仅接受 `--model`、`--effort`、`--max-turns`、`--autocompact`、
`--fallback-model` 的参数对，不能通过环境配置重新开放读写或命令工具。

章节入库前按正式结构索引无损更正唯一可确定的类别和引用，并整理主标签与补充标签的
重复内容。修复校验按迁移后的类别比较内容，修订的根级冲突声明保留历史记录。
歧义类别和真实内容缺失仍须通过原有校验；失败保留断点，不写入无效结构。
标签搬运与去重按两处完整标签内容验收，删除独有标签或正文仍会被拒绝。

### 索引概览容量与恢复

设置 → 模型容量与调用 → **索引概览上限（Token）**，默认 4000。它限制每个证据分片
生成的定位概览，不限制章节正文，也不替代原件。实际额度取设置值、单次输出上限的 1/5、
可用输入预算的 1/16 中的较小值（最低 1）；设置页会显示实际值。
配置键为 `model_overview_tokens`，命令行环境变量为 `ND_CONTEXT_OVERVIEW_TOKENS`。
与其他容量设置一样，新配置只应用于之后启动的新任务，已启动或已入队任务保留配置快照。

概览超限时先有限重试，仍超限则细分证据或收紧归并索引；已完成分片可复用，完整材料不截断。
格式或语义错误不会因此无限分包。材料准备失败会记录阶段、节点、原因和实际调用次数，
不会记成后续修复策略已执行；同一耗尽故障不重复调用模型。调整容量、更新代码或输入证据后，
重启任务会建立新恢复记录并归档旧记录，无需手工清空账本。

跨集合同名须由模型核对原文决定归属，不强制替换为某个角色名。内容保全允许一对一的完整迁移，
要求目标已登记、名称和字段原值保留、不得覆盖同名补丁；不适用的顶层字段原值迁入详情。
迁移仍须通过 Delta 校验与独立原文复核，不能仅以结构校验通过作为语义正确的依据。

主目录、旧工作区与修复分支的整合记录及新版启用步骤见
[分支整合与新版启用说明](docs/分支整合与新版启用说明.md)。

### 运行并发与部署上限

设置 → **运行调度** 可设置分析并发量和分章任务并发量，默认仍为 1 和 2，允许整数 1–32。
上限用于约束桌面端线程资源，不代表模型服务商配额；并发越大不保证越快。
表格按当前表单预览各阶段的配置并发、实际生效上限和限制来源，实际活跃数量还取决于
待处理章节、依赖和其他任务。Delta 与周期治理保持串行校验、顺序归档；交错模式最多
同时运行配置数量的章节分析和一个 Delta，再受部署总上限约束。

部署环境变量 `ND_MAX_CONCURRENT_WORKERS` 为可选的本后端进程共享总上限，仅在启动时读取。
例如分析并发设为 5、部署上限为 2，该任务最多同时运行 2 个模型请求；多个任务合计也不超过 2。
未设置部署上限时，各任务独立使用自身额度，多个任务合计可以超过单任务上限；其他应用实例
和单独启动的外部 CLI 不受本进程限制。无效的环境值会安全降为 1，并在设置和运行日志中说明原因，
修改环境变量后需重启应用。读取部署信息失败时界面显示“未知”，不假定无限制。

任务额度与部署总额度分开计数，最早具备运行条件的请求优先，同任务内保留排队顺序；
一个任务额度已满不会挡住其他有额度的任务。取消等待不会启动模型，结束或异常会释放额度，
排队时间不消耗模型执行超时。单项工作台任务内部仍串行。
保存设置不会热改正在运行的任务或已经入队的全流程配置快照。并发修改不缩减提示词、原文材料或校验规则。

## Windows UTF-8 启动

桌面端 `npm run dev` 在 Windows 上先执行 `chcp 65001` 切换控制台代码页为 UTF-8，再启动
`electron-vite dev`；后端子进程的 spawn env 设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`，
主进程用 `StringDecoder('utf8')` 拼接跨 Buffer 边界的多字节字符，闭环避免中文 stdout/stderr
变成乱码（U+FFFD）。非 Windows 或 CI 直接用 `npm run dev:direct`（即 `electron-vite dev`），
`build` / `typecheck:*` 脚本不受影响。

## 独立工作台（Workbench）

在自动流水线（`/run`、`/queue`）之外，后端提供一套持久化的独立任务工作台。任务由
SQLite 存储，调度线程按项目 FIFO 排队，写者任务（治理 / 章节重跑 / 增量追加）通过
`WriterCoordinator` 与自动流水线互斥共享同一项目的写权限；读者任务（全书分析 / 视觉 /
结构 / 导出）可在写者空闲时并发。任务事件经 `BroadcastHub` 推送到 WebSocket。

### 七个标签页（desktop 桌面端）

- **总览**：项目状态、当前阶段、自动流水线一键运行/取消、任务与陈旧计数摘要。运行前可填写“分析至第 N 章”（含该章）；留空处理全书。输入的截止章按项目自动保存，重启后回填，运行前确认保存成功。截止章限制章节分析、Delta、分章结构、视觉资产与后续全书分析任务包；调大后再次运行会从章节阶段补齐。已提交的后续章节不能通过调小截止章撤回；要分析更短范围可新建项目。
- **章节**：章节卡片（分析 / Delta / 视觉 / 结构四维状态 + 陈旧标记 + 最近任务 + 错误），
  使用连续滚动的虚拟列表，仅渲染可见章节及邻近行，滚动后保留多选状态，支持全书选择与批量重跑。
  列表独立滚动，手动刷新按钮始终可见，列标题固定在列表顶部，无需分页。
  章节页取消定时产物刷新和流水线事件触发的产物刷新，同时暂停项目概况轮询；点击“刷新状态”读取最新任务和产物，任务事件仍同步运行/取消控制状态。
- **分析工作台**：全书分析维度卡片，配置范围（全部 / 区间 / 离散）、目标、问题、原文策略、
  强制重跑，创建 `analysis` 读者任务。`custom` 分析维度需用户自定义问题，故仅在工作台手动触发，
  不进自动流水线 `FULLBOOK_TASKS`。
- **治理**：章节区间与历史，创建 `governance` 写者任务（审计包 → 修正 → 提交，结构校验失败
  自动回滚 before 快照）。
- **导出**：选择 process / final 源、单文件 / Dataview / Canvas / 清空 / 文件名模式，
  创建 `export` 读者任务，产出 Obsidian vault。
  分析完成后可点击“合并章节和分析态”，生成 `导出/故事家完整.json`；它在最终故事结构上
  追加按索引排序的 `章节集`（序号、名称、正文、分析态），供故事家“导入故事家 JSON 文件”使用。
  缺少的单章分析态保留为空字符串，并在导出结果中显示缺失数量；原 `故事结构.json` 不变。
- **维护**：快照恢复、时间线迁移、重新收尾、归一化故事结构、修复 Delta 五项写者任务（详见下文）。
- **日志**：worker 日志文件列表与内容预览；任务/产物抽屉按需打开。

### 任务生命周期

`queued` → `running` → `done` / `failed` / `cancelled` / `interrupted`。重跑（retry）创建新行
并经 `retry_of` 链接旧行，旧行保留。进程重启时残留的 `running` 任务被标记为 `interrupted`，
`queued` 任务在重启后继续调度。事件类型：`task_queued`、`task_started`、`task_progress`、
`task_done`、`task_failed`、`task_cancelled`，每条携带 `task_id` 与 `project_id`。

### 增量追加安全

`POST /projects/{id}/chapters/append-preview` 只读预览（切分新原文、比对旧索引、返回 AppendPlan，
  不写盘）；`POST /projects/{id}/chapters/apply` 将 plan 排入 `append_chapters` 写者任务。apply
  拒绝带前缀冲突的 plan，且只写新增章节 md + 原子更新索引（永不覆盖旧章节）。apply 完成后为
  新 seq 排入 `chapter_analysis_rerun` + `chapter_delta_rerun`，全书分析产物因章节 revision 变化
  而变陈旧。

### 维护

维护标签页把 5 项引擎维护能力暴露为写者任务，按项目写者互斥串行执行（与治理/追加共享同一项目的
写权限），失败时由后端回滚到操作前状态。

- **快照恢复（recover_story）**：`GET /projects/{id}/recover/snapshots` 只读列出
  `故事结构版本/story_after_chNNN.json` 及其可重放到的章节序号；`POST /projects/{id}/tasks`
  提交 `{type: recover_story, params: {snapshot_seq}}` 将过程库回滚到所选快照并重放后续 Delta。
  应用会丢弃所选快照之后的所有过程库改动；失败时后端回滚到恢复前状态。
- **时间线迁移（migrate_chronology）**：对 `故事结构_增量.json` 执行章节时间回填、回溯压缩与
  事件重排，写前生成 `.before_chronology_migration.bak` 备份与 `质量治理/规范化/chronology_migration.txt`
  报告。
- **重新收尾（finalize）**：复合适配器，复刻编排器的 `final_pack -> worker 修订草稿 -> commit_final_draft
  （含修复循环）-> validate_final -> finalize` 链，按需重跑最终整理并写出 `故事结构.json`。
- **归一化故事结构（normalize）**：对 `故事结构_增量.json` 执行保全式规范化（补全缺失集合、迁移
  规范外字段、规范引用），原地覆盖；process revision 变化使相关全书分析产物变陈旧。
- **修复 Delta（repair）**：扫描 `章节处理/第NNN章_*.json`，仅对无法解析的 Delta 调用
  `repair_llm_json` 原地修复（写前备份），已合法的 Delta 不动。

### JSON 权威性

`故事结构_增量.json` / `故事结构.json` 是权威数据源。Markdown 与 Obsidian vault 产物均为只读
镜像，工作台任务从不把它们当输入写回；任务历史与 revision hash 仅描述执行与陈旧状态，不替代
产物校验。

## CodeBuddy 受控故事运行时

章节 Delta 和周期治理默认恢复基线任务包与完整产物交付，原校验和提交失败后才进入自动恢复。
第050章固定输入实测中，基线Delta生成288.625秒、周期治理471.531秒并提交成功；
默认受控循环分别在360/600秒限时后失败，初始上下文变小没有抵消多轮查询的等待。
这是单组样本，不能证明总体正确率提升。显式设置 `ND_CONTROLLED_RUNTIME=1` 才对内置
`codebuddy` 的新生成任务启用下述受控候选协议（默认`0`）：
完整本章/窗口原文进入任务包。小故事档案完整内联，大故事通过冻结的 MCP 按需读取。
内联须同时满足故事估算不超过12000 token、可用输入的1/8、完整初始包不超过可用输入的一半，
为工具和修复留出余量；`ND_RUNTIME_STORY_CONTEXT=tools` 强制使用按需读取作对照，默认`auto`。
这是上下文选择策略，尚不能据单样本认定自动内联更快。`story_read_fields`
按字段分页且返回下一页游标；正式名优先于别名，歧义必须解决后继续。
`candidate_submit` 将完整候选保存、校验和签发凭据合为一次调用，减少模型往返；
`candidate_stage/patch/validate/finish` 保留用于局部修改。工具只能操作任务候选，最终仍由宿主执行合并和完整校验。
提交工具声明七类元素的标准字段、溯源字段和治理类型。标签守恒错误直接列出遗漏及额外标签；
重连时附带当前候选的校验反馈，结构错误仍可修复。字段类型取自统一规范，不把缺省值当成小说事实。
完成回执不等于正式提交成功。其他 provider、自定义命令和超容量分片沿用原有协议。

候选、操作回执与调用预算保存在书籍的 `质量治理/受控任务`；重复 operation ID 不会重复应用，
进程重启不会清空已使用预算。默认每个固定输入任务最多 3 次派发、128 次工具调用、64 次候选修改，
CodeBuddy 最多 32 轮（未显式配置时）；估算上下文预算沿用模型容量设置。
自动恢复的准备子任务也记入实际调用额度，默认最多 24 次、累计执行时间为单次超时的 3 倍，
可通过 `ND_RECOVERY_MAX_WORKER_CALLS` / `ND_RECOVERY_MAX_SECONDS` 配置。
显式 CodeBuddy 的章节/周期治理修复、局部补丁、诊断和独立复核直接通过只读 MCP 查询冻结证据，
不再因为历史库体积大就先调用模型建立全库索引。初始指令仍检查容量；完整故事、原文、候选和
任务约束均保留可读，相关证据必须核对。其他 provider 以及初始指令本身超容量时保留分层路径。
此路由独立于新生成任务的 `ND_CONTROLLED_RUNTIME` 开关，仍沿用原校验、内容保全和独立复核。
预算耗尽时保留候选和原因，不以删除事实、跳过校验或清空账本续跑。

首次定点修复支持字段补丁及同名跨集合迁移：模型只选择已登记的目标集合并提供原文依据，
宿主按参考版本摘要搬移整条内容、保留原值并追加归类理由。禁止越界修改、同名覆盖和隐式合并；
重复登记或无法表达的混合错误保留后续完整修复兜底，仍须通过保全、完整校验与独立复核。
这减少常见身份错置的整份 JSON 重写，不代表所有错误都能用局部补丁修复。

修改目标不存在时，定点补丁还可显式选择 `target_section=新增元素`：仅在正式名称及别名均未登记、
候选内身份唯一、同一集合无目的冲突时提供该选项。模型须先判断真实新事实与旧档案同一性并给原文依据，
宿主保留名称及全部原字段搬移；内容保全按完整迁移比较，不误当删除，完整校验与独立复核仍必需。
已登记身份、歧义或丢字段不因此放行。缺失/空白提取理由可同时补齐，已有实质理由须完整保留。
生成任务明确按正式档案身份选择新增/修改；所属家族已存在，不代表新概括的独立设定已有登记。

章节与治理的本地 JSON 格式化、字段归位和标签压缩在私有候选中执行；成功后记录转换前后
确切摘要再替换产物。内容校验失败不会因此丢失生成凭据，中断后两份已认证字节之一仍可继续验收。
真实故事变化或未经认证的候选改写仍拒绝。旧版治理现场只有在原始快照摘要匹配凭据、且严格 JSON
值完全相同的情况下，才能认定为仅格式化；不以宽松比较放行外部内容变化。

旧标签治理只划分原有标签；新增标签放在修改元素的标签集中。无歧义的纯新增误放入“保留标签”时，
程序将其无损迁到修改元素并保留原理由，继续执行全部原校验和标签压缩。标签遗漏、降级与新增混用、
重复身份、非法标签或冲突写入仍不自动猜测；既有压缩规则可能将受控前缀标签完整移到详情.补充标签。

自动恢复分别保存已生成、已校验、已复核的不可变候选快照。规范化写入中断后从快照重做本地验收；
复核超时/中断后可继续复核，复核通过后中断可继续发布，不重复已完成的模型生成。
复用前核对全部证据副本（包括内容相同或空的文件）与候选摘要，正式输入、代码或配置变化时重新验收。
原生宿主退出按中断处理，不消耗语义策略，但实际调用与已用时间仍计入累计预算。

章节与治理提交共享跨进程写锁。内置CodeBuddy正常直接生成在锁内刷新基线任务包并记录故事版本，
派发前登记pending凭据，结束后锁内发布产物摘要；崩溃或生成期间故事变化时阻止陈旧结果提交。
超容量分片和断点续接也完成同一提交凭据。以上不增加模型工具轮次，也不等于受控模式对全部输入的冻结校验。
带版本凭据的产物发生冲突时保留旧候选，按需进入受控恢复，基于当前
完整证据重新生成；原文、分析或任务身份改变后不能复用旧结果。重试期间再次改变输入会拒绝覆盖。
任务提示词与证据摘要来自同一次字节读取，避免并发改动后给旧提示词签发新版本。
无法使用受控 CodeBuddy 时返回明确失败并保留现场。`ND_CONTROLLED_RUNTIME` 只改变新生成任务的
路由，不绕过已存在的版本凭据，也不禁用版本冲突恢复及故障按需查询。
公共流水线维护入口和工作台规范化、迁移、恢复、修复及重建任务也共用该锁，恢复失败时在锁内
回滚。终稿使用原子替换。供宿主调用的低层转换脚本不重复申请父进程持有的锁；直接运行这些
低层脚本及其他程序编辑文件仍不在统一写者协议内。
宿主已确认最终交付的候选可在重试时直接复验取回；仅通过工具校验、尚未最终交付的候选仍须
恢复模型处理，避免把中途探测结果当作最终产物。两种状态均不代表正式提交已经成功。
本地检查点用于进程故障续接，不等同于异机备份或磁盘故障恢复。

单产物和多产物 worker 均发送排队、执行、耗时及重试事件，概览页另展示逐章提交进度。计时在界面本地更新，
不轮询故事文件。已导入的后端模块不会自动重新加载，完整新流程需在重启应用后的新任务上验证。

固定输入对比入口为 `engine/scripts/runtime_benchmark.py`，只读取事先记录的两组模型结果，
不调用模型、不提交故事。清单每个 case 包含 `name`、`story`、`evidence` 路径数组、可选 `checks`
（`{"path":"/章节","equals":"第001章"}`），以及 `variants.baseline/controlled`。
每组记录 `output`、生成时的 `input_fingerprint`，可选真实测量的 `elapsed_seconds`、`input_tokens`、
`output_tokens`、`tool_calls`、`retry_count`。路径相对于清单；指纹用同模块的
`evidence_fingerprint(清单目录, evidence)` 在生成前记录，两组必须使用同一冻结输入。

```powershell
runtime\venv\Scripts\python.exe -X utf8 engine\scripts\runtime_benchmark.py benchmark.json --output comparison.json
```

报告分别显示结构校验、人工标注检查和已测耗时；缺少标注或耗时保持未知，输入不一致不计算提速。
人工标注只覆盖明确列出的事实，结构合法性不等于全量语义正确。2026-10-13 的独立合成样本实测中，
合并工具调用后受控 Delta 从约192秒降到145秒，但同样本旧路径约73秒；不能声称新路径整体更快。
周期治理仍观察到契约纠错与超时，部署前需要扩大真实固定样本和中断续接验证。
实施记录见 `docs/superpowers/plans/2026-10-13-controlled-story-runtime.md`。
